# facts: 言い切る前の関門

2026-11-07 オーナー指示。過去19セッションの記録から作った。誤りをゼロにはできない。言い切りを減らし、外れた時にすぐ気づけるようにするもの。

## 主張の種類
発言は5種類のどれかに当たる。種類ごとに、言ってよい根拠が決まっている。

| 種類 | 言ってよい根拠 | 根拠が無い時の言い方 | 実際に外れた例 |
|---|---|---|---|
| 状態（版・PR・配信・設定） | その場で見た `git`・`gh`・EAS・ストアの画面 | 「最後に見たのは◯月◯日」 | 索引の「main a11c2d1」は #105 のマージで古くなっていた（11-07） |
| 原因 | 再現した、または反する証拠を探して出なかった | 「〜と見ている。次に◯◯で確かめる」 | Expo Go で「原因が分かった」と2回続けて外し、本当は iPhone 側のログインだった（10-30） |
| 仕様（ライブラリ・API・ほかのアプリ） | `node_modules/<名前>` の型定義と本体、版の合う公式文書、実行結果 | 「試すまで不明」 | 「Amicuna のような丸ゴシック」と書き、開いたら Noto Sans JP だった（10-29） |
| 完了 | 実物で見た範囲だけ。テスト合格は画面の確認ではない | 「テストは通った。iPhone では未確認」 | 今回の調査では確かな例なし（下の「調べ方の限界」） |
| 手順（オーナーへの案内） | 読んだコード、または見た画面 | 手順の最後に「違う画面なら、そのまま教えてください」 | 下の「見えないもの」 |

## 見えないもの
いちばん多く外れたのは手順で、原因は見えないものを想像で書いたこと。

- オーナーの画面は見えない。「黒い画面」と案内したら白かった（10-24）
- オーナーの持ち物を決めつけない。iPhone は1台（10-30、2台ある前提で案内した）
- 確かめ方を案内する前に、その動きのコードを読む。「会議を2つ入れて」と案内したが、続いた同じ名前の予定は1つにまとまる（10-30）

## メモリーの書き方
- 古くなる速さで置き場所を分ける。決まりごとはそのまま信じてよい。コードの説明は Grep で確かめる。版・PR・配信はすぐ古くなるので、書くなら日付を付け、索引の1行には書かない
- 日付つきの記録は今の根拠にしない
- 書く前に実物を見る。覚えていることをそのまま書かない

## 機械の仕組み（`.claude/hooks/factGate.js`）
- 始まる時に「今の実物」（ブランチ・HEAD・版）を文脈へ入れる。Desktop は起動時にフックが届かないことがあるので、文脈に無ければ自分で `node .claude/hooks/factGate.js < /dev/null` を動かす
- 終わる時に報告を読み、原因・完了の言い切りに未確認の行が無い時、手順に「違ったら」の行が無い時に1回だけ止める
- 見ているのは言い回しだけで、中身の真偽は分からない。通っても正しいとは限らない
- 規則を変えたら `src/factGate.test.ts` も変える
- Desktop の実際のセッションで動くかは 2026-11-07 時点で未確認。確かめたらこの行を消す

## 仕様の調べ方
- `code.claude.com` には届かなかった（2026-11-07、DNS エラー）。Claude Code のフックの項目は、npm で入れた `claude.exe` を `grep -a` して定義を読んで確かめた

## 調べ方の限界
過去の記録はキーワードで探した。オーナーが気づかなかった誤りは数えていない。件数は多い少ないの目安にとどまる。
