# guardrails: 衝突判定の規則（src/engine）

入口は `computeGuard({starts, settings, keywords, events, range})`（`guard.ts`）→ `{prediction, zones, alerts}`

## 周期予測（cycle.ts）
- 当たり具合（accuracy.ts、2026-10-31）: 前の開始日との間が15〜45日の時だけ比べる（記録漏れは数えない）。直近6回、3回未満なら平均と±1日以内率は null（0日と見せない）。誤差0日は「予測どおりでした」
- 受診の目安（consult.ts、2026-10-31）: 直近6回の間隔（3回そろうまで出さない）で、15日未満・45日超が2回以上（frequentExclusion＋short/longCycle）か、15〜45日の間隔どうしの最短と最長が10日以上（highSpread）。文は記録の傾向＋「婦人科に相談するという目安もあります。判断は医師にご相談ください。」だけ。病名・「可能性が高い」・警戒/警告/危険/診断/治療/絶対/100%/保証は使わない（テストで確認）
- 直近6周期の平均。15〜45日以外の間隔は除外（記録漏れ扱い）し、`excluded` に理由（tooShort/tooLong）つきで返す
- 有効な周期が3未満なら28日±2日の仮予測（`provisional: true`、確信度 low）
- n回目の予測は `predictedPeriod`。幅は平均±標準偏差（`spread`、最低1日）で固定（先に行くほど広げない）
- 確信度: 周期4つ以上かつ幅4日以内→high／2つ以上かつ8日以内→medium／それ以外→low

## 警戒ゾーン（zones.ts）
- 既定 `heavyDays=3`（1〜7）, `pmsDays=7`（0〜14）。`validateZoneSettings` で検査
- heavy: 記録した開始日すべてから heavyDays 日（前の月を見ても塗る。2026-10-30）+ 予測の earliest〜(latest+heavyDays-1)
- pms: (earliest − pmsDays) 〜 latest の前日。heavy が優先
- PMS の日数（pms.ts、2026-10-31）: 自動が既定。開始日ごとに直前14日の答えを近い順に見て「きつかった」が途切れず続いた一番遠い日＝その周期の始まり（生理中の答えは除く）。最近6周期そろい標準偏差≤2日の時だけ平均を3〜14日で使う（それまで7日前）。変わった日（appliedFrom）より前に始まる帯は前の日数のまま（`pmsBefore`）。手動（設定の日数0〜14）は学習で変えない
- 含まれない日は「通常/回復期」で警告対象外
- `periodPhase(day, zones)`: pms→before / heavy→during / ヘビー期の翌日から`AFTER_PERIOD_DAYS`(4)日→after。心の変化の目安表示用で、警告・通知には使わない

## 予定のリスク（risk.ts）
- 終日予定は high。ただし「有給」「休暇」「代休」「OFF」を含む予定と、祝日カレンダー（名前に 祝日/holiday）の予定は除く（2026-10-30 F7）
- 覚えた重さ（`keywords.learned`、`termOf`＝NFKC・小文字・空白除去の名前全体ごと）が言葉と終日より優先: heavy→high / normal→medium
- `learnWeight`（learning.ts）: きつかった は時期を問わず重い向き、生理/PMS中の ふつう/平気 はふつう向き、落ち着いた時期の ふつう/平気 は向きを変えない。同じ向きが2回続くと決まる。設定で直したもの（source user）は答えで変えない
- タイトルをNFKC＋小文字にしてキーワードを部分一致。high を先に判定
- 既定 high: 出張 プレゼン 発表 面接 旅行 ライブ 遠征 夜勤 締め切り 締切 試験
- 既定 medium: 会議 打ち合わせ 打合せ ミーティング 飲み会 美容院 残業 ワンオペ
- キーワードはユーザーが設定で編集できる（DB の `keywords`）

## 判定（conflicts.ts、2026-10-30 から点数と A/B/C）
- 点数 = 100 × 時期 × 予定の重さ × (1 + 加点)。0〜100 に丸める。70以上 A（要注意）/ 40以上 B（注意）/ それ未満 C（参考。出さない・通知しない）
- 時期: 生理1〜3日目 1.0 / 生理4日目以降（ヘビー期を長くした時）・予測の端 0.6 / PMS 0.7 / 生理のあと（ヘビー期の翌日から）とそれ以外 0.1。排卵の時期は計算しない（2026-10-30 オーナー確認: 生理のあとは要注意にしない）
- 予定の重さ: high 1.0 / medium 0.4 / low 0（出さない）。終日は +0.2（終日は high）
- 加点: 終日で移動の言葉（出張・旅行・遠征・帰省・合宿）+0.15 / 8時より前に始まる +0.05。4時間以上は理由だけ（longDuration）
- 予測の確信度が「低」の日は理由に windowWide と注記を付ける
- 同じ名前（NFKC・小文字）の予定が日をあけずに続く時は1件にまとめる（`series.ts` の groupSeries、memberIds に元のID）。名前が違えばまとめない
- 何日も続く予定は +0.15（seriesPeak）。丸める前の点数がいちばん高い日（同じなら早い日）を1件だけ出し、`series.days` に日ごとの点数と名前を添える。並び: A が先、同じなら日付順
- 理由の1行（reasonText）は必ず出す。提案（message）は提案口調で断定しない
- 係数は名前付きの定数。設定画面には出さない

## 動かせるかと対処（conflicts.ts の impactOf、actions.ts の planActions）
- 動かせない（面接・試験・締め切り・夜勤・結婚式・葬儀・本番）/ 動かせる（会議・飲み会・美容院・ランチ・旅行・帰省など）/ それ以外は「準備で軽くできる」
- 別の日の候補は「動かせる」予定だけ。前後14日で、予定の全部の日が落ち着いている時期（ゾーン外・生理の終わりごろ外）から近い順に3つ。今日より前は出さない
- 期限は予定の日から 旅行・帰省7日 / 出張・遠征3日 / 面接・試験2日 / 会議1日 / それ以外3日 前
- 断りの文は「動かせない」以外に付ける。相手に送る文なので体調・生理・PMSは書かない

## 通知の予定（notifications.ts）
- 1つの予定の通知（2026-10-31 Phase 3）: 判断期限（`planActions` の deadline）・「今日は決めない」の翌日・7日前（A）・3日前の順に違う日を3つまで。過ぎた日も数えて選ぶ（日がたっても入れ替わらない）。今日より前の分は作らない。翌日が予定の日以降なら知らせ直さない
- 同じ日の通知は1件にまとめる（id `guard-YYYY-MM-DD`）
- 「どうだった？」（`planReviewNotifications`、id `review-YYYY-MM-DD`）: 重い・ふつうの予定の最後の日の次の朝9時、朝1件（重い予定を先）。答えた予定は聞かない。ボタン きつかった/ふつう/平気だった/答えない は押すとアプリが開く（開かないボタンはアプリ終了中だと答えを受け取れない）
- ホームの「予定、どうだった？」（`pendingReviews`）: 終わって7日以内・未回答を新しい順に3件。答えない＝学ばない。1つの予定で数えるのは最初の答えだけ。時期は予定の日のゾーン（記録した開始日の pmsDays 日前も PMS）
- 本文は判断期限＋具体策2つまで（「11/17までに決めれば間に合います（11/29に変える／前後の予定をゆるめにする）」、期限当日は「今日中に」、過ぎたら「決める目安の…は過ぎました。いまからでも：…」）。動かせる=決めれば、準備で軽くできる=準備を始めれば、動かせない=準備を終えれば。動かせない予定には別の日を勧めない。通知が届く日に過ぎている別の日は勧めない
- 通知はロック画面に出るので、生理・PMS・体調につながる言葉（と日付入りの準備）を入れない（`NOT_IN_NOTIFICATIONS`）。複数の予定の日は1行ずつ「11/12 出張：…」

- お知らせタブのボタン→ `Share.share` の共有メニューだけで送る（LINE SDK・URL・通信は入れない）
- 見本はオーナー指定の8文（2026-10-28 差し替え。省エネモード／緊急速報／ポンコツ化／HPほぼゼロ／体調重め／イライラごめん／予定ゆっくり／マイペース）。日付・予測・予定・記録の中身は入れない。入力欄で自由に書き換えられ、見本を押すと元の文に戻る（保存しない）
